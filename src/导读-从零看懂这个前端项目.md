**函数名、变量名、常量名都是自解释的**，而且这个项目的命名很规范：

| 你看到的名字 | 说明 |
|---|---|
| `getItemList` / `createItem` / `updateItemStatus` | api 层函数，名字基本就是契约里的接口名 |
| `toBrief` / `toItem` / `toStatusPatch` | **`to` 开头 = 转换函数**（把后端原始数据变成内部形状） |
| `useUnreadPolling` / `useUserStore` | **`use` 开头 = 组合式函数或 Pinia store** |
| `Raw` 开头（如 `RawPost`） | **后端的原始数据形状**（下划线字段名） |
| `API_` / `ROUTE_` 开头 | 接口路径 / 页面路径（**这两类绝不能混用**，混了会白屏） |
| `mock` 开头 | 假后端的函数，和 api 层的真函数一一对应 |

>

## 第 1 章　前端基础：先搞懂这几件事

### 1.1 浏览器只认三种语言

| 语言 | 管什么 |
|---|---|
| **HTML** | 结构（页面上有哪些东西） |
| **CSS** | 样式（长什么样：颜色、大小、位置） |
| **JavaScript** | 行为（点击之后干什么） |

**TypeScript** = JavaScript + 类型标注。浏览器**不认 TS**，要编译成 JS（`npm run build` 干这事）。

### 1.2 那 `.vue` 文件是什么？

一个 `.vue` 文件**固定就是三段**：

```vue
<script setup lang="ts">
// ① 逻辑：变量、函数
</script>

<template>
  <!-- ② 界面：写 HTML -->
</template>

<style scoped>
/* ③ 样式：只管这个文件 */
</style>
```

| 名词 | 意思 |
|---|---|
| **组件（component）** | 一个 `.vue` 文件就是一个组件 = 一块可以复用的界面 |
| **`<script setup>`** | 固定写法，意思是"这个文件里的东西默认可以直接在模板里用" |
| **`scoped`** | 这段 CSS 只影响本文件，不污染别人 |

> **不写 `scoped` 会怎样？** A 页面写 `.title { color: red }`，
> B 页面所有 `.title` 也跟着变红。这种 bug 很难查。

### 1.3 ⭐ 核心机制：数据变了，界面自动变

**这是整个前端最重要的一句话。** 看真实代码（`components/PostTable.vue` 第 88 行）：

```ts
list.value = res.list     // 只改了这一行
```

**改完这一行，界面上的表格就自己变了。没有一行代码去操作 HTML。**

三种写法的对比（你的算法竞赛思维在这里很好用）：

| 写法 | 代码长什么样 | 特点 |
|---|---|---|
| **命令式** | 先找到表格元素，再一行行 `appendChild` 塞进去 | 每改数据你得手写一遍"界面怎么改" |
| **声明式**（Vue 用这个） | 只写 `list.value = res.list` | 你说"数据该是什么"，Vue 算"界面怎么变" |

> **算法竞赛类比**：
> - 命令式 = 自己写 `for` 循环维护前缀和数组
> - 声明式 = 直接用 `std::sort`，你只说"排个序"
>
> `ref` 就是把变量登记成"Vue 会盯着的东西"。

## 第 2 章　程序怎么跑起来的（3 个节点）

### 节点 ①：`index.html`

整个应用**只有一个** HTML 文件，它只提供一个空壳：

```html
<div id="app"></div>
```

> 别的页面都是 JS 在运行时"画"进这个 div 里的。所以你在浏览器里看到的
> 所有内容，**都不是这个 HTML 里写死的**。

### 节点 ②：`src/main.ts` —— 启动

```ts
initTheme()                       // 先定主题，避免闪一下
const app = createApp(App)        // 造一个 Vue 应用
app.use(createPinia())            // 装上"全局状态"插件
app.use(router)                   // 装上"路由"插件
app.use(ElementPlus)              // 装上"UI 组件库"插件
app.mount('#app')                 // 挂到 index.html 那个 div 上
```

| 名词 | 大白话 |
|---|---|
| **`app.use(插件)`** | 给这个应用装一个"外挂能力" |
| **`mount('#app')`** | 把 Vue 应用挂到 HTML 的那个 div 上 |
| **Pinia** | 全局变量表（多个页面共享数据用） |
| **Router** | 管"地址栏 → 显示哪个页面" |
| **Element Plus** | 别人写好的按钮/表格/弹窗，我们直接用 |

### 节点 ③：`src/App.vue` —— 根组件（只有 5 行）

```vue
<template>
  <RouterView />
</template>
```

**`<RouterView />` 的意思**：这里是个"插座"，地址栏变了，
路由就决定往这个插座里插哪个页面。

```
App.vue（根，只放一个插座）
   └─ UserLayout.vue（用户端外壳：页头 + 菜单 + 插座）
        └─ ItemList.vue（首页）
        └─ ItemDetail.vue（详情页）
        └─ Messages.vue（消息）
        ...
```

> **这就是"页面嵌套"的概念。** 外壳写一次（页头、菜单），
> 里面换页面时外壳不动，只换插座里的内容。

## 第 3 章　完整走一遍：点"登录"之后发生了什么

**建议：把这一章和第 3.5 节的"对照着读"配合使用，打开真实文件边看边读。**

### 3.1 五个节点总览

```
① views/LoginView.vue      用户点了"登录"按钮
        ↓ 调用 handleSubmit()
② api/auth.ts              把参数整理成后端要的格式，发请求
        ↓ 调用 http()
③ utils/request.ts         统一贴 token、统一处理错误、统一"拆壳"
        ↓
④ mock/index.ts            假后端（USE_MOCK=true 时）
   或 真后端（8000 端口）
        ↓ 数据回来
⑤ stores/user.ts           把 token / 角色 / 用户名存起来
        ↓
   router.push('/')        跳到首页
```

### 3.2 节点①　页面收到点击

**`views/LoginView.vue` 的模板部分：**

```vue
<el-button @click="handleSubmit">登录</el-button>
```

| 语法 | 意思 |
|---|---|
| `@click` | `@` = 绑定事件。`@click="handleSubmit"` = "被点击时执行 handleSubmit 函数" |
| `handleSubmit` | 注意**没写括号**！写成 `handleSubmit()` 会变成"页面一加载就执行" |

**同文件里的 `<script>` 部分：**

```ts
async function handleSubmit() {
  const res = await login(params)   // ← 调用 api 层
  userStore.setLogin(res)           // ← 存到全局状态
  router.push(redirect)             // ← 跳页
}
```

| 语法 | 意思 |
|---|---|
| `async` / `await` | 表示"等这个请求回来再往下走"。**JS 里所有网络请求都要 await** |
| `const res = await login(...)` | `res` 就是后端返回的数据（已经拆过壳） |
| `router.push('/')` | 跳到某条路径（**不刷新页面**，只是换内容） |

### 3.3 节点②　api 层整理参数

**`api/auth.ts`：**

```ts
export async function login(data: LoginParams): Promise<LoginResult> {
  if (USE_MOCK) {                    // 假后端模式
    await delay()
    return mockLogin(data)
  }
  const res = await http<Record<string, unknown>>({   // 真后端模式
    url: API_LOGIN_PATH,             // '/auth/login'
    method: 'post',
    data: { [LOGIN_ID_FIELD]: data.studentId, password: data.password },
  })
  return { /* 把下划线字段转成驼峰 */ }
}
```

**这里有两件事你要理解：**

**① `if (USE_MOCK)` 这个分叉**

这是整个项目的前后端解耦机制：

| `USE_MOCK` | 走哪条路 |
|---|---|
| `true`（现在） | 走 `mock/index.ts` 的假数据，**不需要后端** |
| `false` | 走真后端（`vite.config.ts` 里代理到 `127.0.0.1:8000`） |

> **好处**：页面代码一行都不用改，只改这一个开关。

**② 字段名转换（下划线 ↔ 驼峰）**

| 后端返回 | 我们内部用 |
|---|---|
| `student_id` | `studentId` |
| `avatar_url` | `avatarUrl` |
| `created_at` | `createdAt` |

> **为什么要转？** 后端的 JSON 规范是下划线，前端 JS 的惯例是驼峰。
> 转换**只在 `src/api/*.ts` 里发生**，页面永远只看到驼峰。
> 这样后端改字段名，只改一个文件。

### 3.4 节点③　网络层做四件事

**`utils/request.ts`** 是所有请求的必经之路：

| 做的事 | 为什么 |
|---|---|
| 请求发出前自动贴 `Authorization: Bearer {token}` | 不然每个请求都得手写一遍 |
| 响应回来后自动"拆壳" | 后端格式是 `{code, message, data}`，我们只要 `data` |
| 出错时统一弹红字提示 | 不然每个页面都要写一遍 `ElMessage.error(...)` |
| 令牌过期自动换新的再重试 | 用户无感（这叫"无感刷新"） |

| 名词 | 大白话 |
|---|---|
| **拦截器（interceptor）** | 一个"中间人"：请求出门前他检查一遍，响应进门后他也检查一遍 |
| **拆壳** | 后端包了三层 `{code, msg, data}`，我们只把 `data` 交给业务代码 |
| **`http<T>(...)`** | 我们封装的发请求函数，`<T>` 是"返回值的类型"（泛型和 C++ 模板一个意思） |

### 3.5 节点⑤　存进全局状态

**`stores/user.ts`：**

```ts
export const useUserStore = defineStore('user', () => {
  const token = ref(localStorage.getItem('token') ?? '')   // 从本地存储恢复
  const role = ref<UserRole>('student')
  const userId = ref(0)

  function setLogin(info: UserInfo) {
    token.value = info.token
    localStorage.setItem('token', info.token)   // 写进浏览器本地存储
  }
  function logout() { /* 清干净 */ }

  return { token, role, userId, setLogin, logout }
})
```

| 名词 | 大白话 |
|---|---|
| **Store（仓库）** | 全局变量表。多个页面都能读写同一份数据 |
| **`localStorage`** | 浏览器的"本地硬盘"。存进去的值，**关掉浏览器再打开还在** |
| **为什么 token 要存 localStorage？** | 不然刷新页面（F5）就"忘了"你登录过 |

> ⚠️ **`localStorage` 只能存字符串**。存数组/对象要先 `JSON.stringify`。

## 第 4 章　语法速查表（你每天都会见到的）

### 4.1 ⭐ 两种"响应式"变量：`ref` vs `reactive`

**这是最容易忘的规则，先背这个表：**

| | `ref` | `reactive` |
|---|---|---|
| 存什么 | 单个值（数字/字符串/数组/对象都行） | **只能是对象** |
| 写法 | `const loading = ref(false)` | `const form = reactive({ name: '' })` |
| 读/写 | 必须 `loading.value = true` | 直接 `form.name = 'x'` |
| 模板里 | **不用写 `.value`**（Vue 自动脱） | 不用写 |
| 本项目的用法 | `ItemList` 的 `list` / `loading` | `LoginView` 的 `form` |

```ts
// ref：单个值
const loading = ref(false)
loading.value = true          // ✅
loading = true                // ❌ 报错（const）

// reactive：一个对象
const form = reactive({ studentId: '', password: '' })
form.studentId = '2021001'    // ✅ 不用 .value
```

> ⚠️ **`reactive` 有个坑**：不能整个替换，也不能解构。
> ```ts
> let form = reactive({ a: 1 })
> form = reactive({ a: 2 })        // ❌ 失去响应式
> const { a } = form               // ❌ 解构后 a 不是响应式的
> ```
> 所以本项目里"会被整个替换的数据"一律用 `ref`（比如 `list`）。

> **算法竞赛类比**：`ref` = 套了层可观测代理的指针；`reactive` = 整个结构体加上了监听。

### 4.2 模板语法（写在 `<template>` 里）

| 写法 | 名字 | 意思 | 例子 |
|---|---|---|---|
| `{{ x }}` | **插值** | 把变量的值显示出来 | `<span>{{ detail.title }}</span>` |
| `v-model="x"` | **双向绑定** | 输入框和变量**互相同步** | `<el-input v-model="form.password" />` |
| `:attr="x"` | **属性绑定** | `:` = 后面是**变量**不是字符串 | `:src="avatarUrl"` / `:limit="1"` |
| `@click="fn"` | **事件绑定** | `@` = 绑定事件 | `@click="handleSubmit"` |
| `v-if="x"` | **条件渲染** | 假就**销毁**这个元素 | `v-if="userStore.isLogin"` |
| `v-else` | | 配 `v-if` 用 | |
| `v-show="x"` | | 假就 `display:none`（元素还在） | |
| `v-for` | **列表渲染** | 循环生成元素 | `v-for="o in list" :key="o.id"` |

**⚠️ 三个最容易错的地方：**

```vue
<!-- ① 属性绑定必须加冒号！不然传的是"字符串" -->
:limit="1"        <!-- ✅ 传数字 1 -->
limit="1"         <!-- ❌ 传字符串 "1" -->

<!-- ② @click 不要写括号（除非你要传参数） -->
@click="handleSubmit"        <!-- ✅ 点击时才执行 -->
@click="handleSubmit()"      <!-- ❌ 页面一加载就执行了 -->

<!-- ③ v-for 必须配 :key，且要唯一 -->
v-for="o in list" :key="o.id"   <!-- ✅ -->
v-for="o in list"               <!-- ❌ Vue 会警告，且可能渲染错乱 -->
```

> **`:key` 是干什么的？** 帮 Vue 认出"这一项还是原来那一项"。
> 用 `index` 当 key 是常见的坏习惯（删掉第一项后，后面所有 index 都变了）。

### 4.3 事件修饰符

| 写法 | 意思 |
|---|---|
| `@click.stop` | 阻止事件冒泡（点了我，别让我爸也响应） |
| `@click.prevent` | 阻止默认行为（比如表单提交后刷新页面） |
| `@submit.prevent` | 上面两个的常见组合，表单上都这么写 |
| `@keyup.enter` | 只在按回车时触发 |
| `@keyup.enter.ctrl` | 只在 Ctrl+回车时触发 |

**真实例子**（`views/user/Messages.vue`）：

```vue
<!-- 点头像 -> 进用户主页；.stop 是为了不让"整行点击"也触发 -->
<el-avatar @click.stop="router.push(userProfilePath(row.peer.id))" />
```

> **`.stop` 为什么必要？** 因为那个头像是包在"整行可点"的 div 里的。
> 不写 `.stop` 的话，点头像会**同时**触发"进用户主页"和"进聊天页"两个动作。

### 4.4 父子组件之间怎么传数据

| 方向 | 语法 | 大白话 |
|---|---|---|
| 父 → 子 | 子组件写 `defineProps<{ mine?: boolean }>()` | 子组件声明"我需要什么参数" |
| | 父组件写 `<PostTable mine />` | 把参数传下去 |
| 子 → 父 | 子组件 `defineEmits(['search'])` 然后 `emit('search')` | 子组件喊一声"出事了" |
| | 父组件写 `@search="fetchList"` | 接到喊声就执行 |

**真实例子**：`ItemList.vue`（父，12 行）用 `PostTable.vue`（子）：

```vue
<!-- 父：ItemList.vue -->
<PostTable />          <!-- 首页：不带参数 -->

<!-- 父：MyPosts.vue -->
<PostTable mine />     <!-- 我的发布：传一个 true -->

<!-- 子：PostTable.vue -->
const props = withDefaults(defineProps<{ mine?: boolean }>(), { mine: false })
// props.mine 就是上面传进来的值
```

> **`?` 是什么意思？** 类型里的 `mine?: boolean` 表示**这个参数可选**（可传可不传）。
> 不写 `?` 就是必填。
>
> **`withDefaults(..., { mine: false })`** = 给可选参数一个默认值。
> C++ 类比：`bool mine = false` 的默认参数。

### 4.5 常见 TypeScript 语法（按你见过的频率排序）

| 语法 | 名字 | 意思 | 例子 |
|---|---|---|---|
| `x: string` | 类型标注 | 声明这个变量是字符串 | `const name: string = 'x'` |
| `x \| null` | **联合类型** | "要么是 A 要么是 B" | `phone: string \| null` |
| `x?: T` | **可选属性** | 可传可不传 | `mine?: boolean` |
| `interface X { }` | 接口 | 描述一个对象长什么样 | `interface Item { id: number }` |
| `type X = A \| B` | 类型别名 | 给类型起个名字 | `type ItemType = 'lost' \| 'found'` |
| `as const` | 常量断言 | 定死成字面量，别推断成宽泛类型 | `export const Role = { ADMIN: 'admin' } as const` |
| `import type { X }` | 只导入类型 | 运行时会被删掉（不影响打包体积） | `import type { Item } from '@/types/api'` |
| `x?.y` | **可选链** | `x` 是空的就返回 `undefined`，**不报错** | `detail?.title` |
| `x ?? y` | **空值合并** | `x` 是 `null`/`undefined` 就用 `y` | `raw.phone ?? null` |
| `x!` | 非空断言 | "我保证它不是空的" | `list[0]!.id` |
| `x as T` | 类型断言 | "就当它是 T"（编译器不检查） | `route.query.redirect as string` |
| `enum`-like | 用 `as const` 代替枚举 | 见下面 | |

**⚠️ `??` 和 `||` 的区别（很重要，本项目踩过坑）：**

```ts
0 ?? 5      // 0     ← 只判断 null/undefined
0 || 5      // 5     ← 0 是"假值"，所以被换掉了！
false ?? true   // false
false || true   // true  ← 这就是 bug 的来源
```

**真实教训**：`isRead` 参数有三种含义（不传=全部 / `false`=只看未读 / `true`=只看已读），
写成 `if (params.isRead)` 会把 `false` 漏掉，行为正好相反。
正确写法是 `if (params.isRead !== undefined)`。

> **判空表（按严格程度）**：`if (x)` < `if (x !== undefined)` < `if (x !== null && x !== undefined)`
> 不确定时用最严格的。

### 4.6 其它常见语法

| 语法 | 意思 | 例子 |
|---|---|---|
| `async` / `await` | 等异步操作完成 | `const res = await getItemList(...)` |
| `try / catch / finally` | 出错了怎么办 | `finally` 里放"无论如何都要做的事" |
| `Promise<T>` | "未来会有一个 T" | 函数返回它表示"这是异步的" |
| `arr.map(x => ...)` | 每个元素变换一次，返回新数组 | `list.map(toBrief)` |
| `arr.filter(x => ...)` | 筛选 | `list.filter(c => c.isRead)` |
| `arr.find(x => ...)` | 找第一个满足的 | `list.find(m => m.id === 5)` |
| `\`Hi ${name}\`` | 模板字符串 | 反引号，里面可以插变量 |
| `const { a, b } = obj` | 解构赋值 | 把对象的字段取出来当变量 |
| `[...arr1, ...arr2]` | 展开运算符 | 合并数组 / 复制 |
| `x => x + 1` | 箭头函数 | 相当于匿名函数 |
| `.at(-1)` / `arr[i]` | 取元素 | ⚠️ 本项目开了 `noUncheckedIndexedAccess`，`arr[0]` 的类型是 `T \| undefined`，所以常见 `arr[0]!` |

### 5.4 最容易混的两组词

**① `ref` 有两个完全不同的意思**

| 场景 | 意思 | 例子 |
|---|---|---|
| 声明响应式数据 | 一个"会被盯着"的值，要 `.value` | `const list = ref([])` |
| 模板引用（template ref） | 拿到真实 DOM 元素或子组件实例 | `const formRef = ref<FormInstance>()` |

怎么区分？**看它是不是在 `<template>` 里用 `ref="同名字符串"` 绑过**：

```vue
<el-form ref="formRef" ...>           <!-- 模板里绑了 -->
```
```ts
const formRef = ref<FormInstance>()   // 这个是为了拿到表单实例，调它的 validate()
formRef.value?.validate()             // 所以这里才有 .value
```

**② `?` 有三种完全不同的用法**

| 出现位置 | 意思 | 例子 |
|---|---|---|
| 类型里 | 可选属性 | `mine?: boolean` |
| 变量后 | 可选链 | `detail?.title` |
| 函数名前 | 可选调用（模板里常见） | `formRef.value?.validate()` |

## 附：本项目"一眼就会"的高频写法

把下面这 10 行背下来，你就能读懂 80% 的页面代码：

```ts
// 1. 声明响应式数据
const loading = ref(false)
const list = ref<ItemBrief[]>([])
const query = reactive({ page: 1, keyword: '' })

// 2. 拉数据（固定套路：loading 开 → try 拿数据 → catch 清空 → finally 关 loading）
async function fetchList() {
  loading.value = true
  try {
    const res = await getItemList({ page: query.page, keyword: query.keyword })
    list.value = res.list          // ← 就靠这一行，界面自己更新
  } catch {
    list.value = []                // ← 出错也要让界面有东西显示，别白屏
  } finally {
    loading.value = false
  }
}

// 3. 页面加载时自动拉一次
onMounted(fetchList)

// 4. 参数变了就重新拉
watch(() => query.page, fetchList)
```

```vue
<!-- 5. 表格/列表渲染 -->
<div v-for="row in list" :key="row.id" @click="handleOpen(row)">
  {{ row.title }}
</div>

<!-- 6. 条件显示 -->
<el-button v-if="detail?.canDelete" @click="handleDelete">删除</el-button>

<!-- 7. 输入框双向绑定 -->
<el-input v-model="query.keyword" @keyup.enter="fetchList" />

<!-- 8. 加载动画（v-loading 绑一个布尔值） -->
<div v-loading="loading"> ... </div>

<!-- 9. 空状态 -->
<el-empty v-if="list.length === 0 && !loading" description="还没有数据" />

<!-- 10. 弹提示 -->
<!-- ElMessage.success('操作成功')   ← 这行写在 <script> 里 -->
```
