# 部署说明（打包 / 交付给后端）

> 这份文档回答一个问题：**怎么把前端交给后端部署，以及怎么确认交对了。**
>
> 项目学习向的内容看 [`导读-从零看懂这个前端项目.md`](./导读-从零看懂这个前端项目.md)。

## 一、后端的要求（2026-10-05 原话）

> 前端的部署我这边来（服务器 + nginx），你把 `npm run build` 的产物 `dist/` 压缩发我就行。
>
> 你本地 dev 用的那个 vite proxy 打包后不生效（那个只对 `npm run dev` 有效），
> 所以不用管接口地址 —— 代码里 `API_PREFIX = '/api/v1'` 是相对路径，
> 我这边 nginx 会反代到后端。
>
> 只要确认 `npm run build` 能正常过就行。

**三条要求拆开看：**

| # | 要求 | 我们这边的情况 |
|---|---|---|
| 1 | 交付 `npm run build` 的 `dist/` | ✅ 能过，产物 38 个文件 / 1502.9 KB |
| 2 | 接口地址用相对路径，不用改 | ✅ 本来就是 `/api/v1` 相对路径 |
| 3 | 确认 `npm run build` 能过 | ✅ 退出码 0（下面有验证方法） |

## 二、⚠️ 最容易踩的坑：假数据总开关

### 问题是什么

`src/mock/index.ts` 里有这一行：

```ts
export const USE_MOCK = !import.meta.env.PROD
```

**在这行改成这样之前，它写死的是 `true`。** 后果非常严重：

> 打包出来的 `dist/` 部署上去，**跑的是假数据（张三、李四、王老师那些），根本不会请求后端**。
> 后端配好的 nginx 反向代理完全落空。

这种问题最阴险的地方是：**页面能打开、有数据、不报错、不白屏**，看着一切正常。
如果不认真核对，会一直以为部署成功了。

### 现在的行为

| 命令 | 构建模式 | `USE_MOCK` | 走哪条路 |
|---|---|---|---|
| `npm run dev` | development | `true` | 假数据（本地开发用，**多人协作不受影响**） |
| `npm run build` | production | **`false`** | **真实后端** |

### ⚠️ 为什么必须写成"编译期常量"

不能改成运行时读配置（比如读 `window.xxx` 或全局变量），否则会出两个问题：

1. 各页面里写的是裸的 `if (USE_MOCK)`，只有它被**静态求值**，打包器才能处理那条死分支
2. 如果改成运行时变量，"生产环境永远为 false"这件事就没人保证了 —— 又回到"可能带着假数据上线"

**一句话：这个开关的值必须在打包那一刻就定死。**

### 怎么确认打包出来的真是"走真后端"

有三种查法，从快到慢：

**方法 1（最快）：看源码那一行**

```powershell
Select-String -Path 'src\mock\index.ts' -Pattern 'export const USE_MOCK'
# 期望输出：export const USE_MOCK = !import.meta.env.PROD
```

**方法 2：打包后搜产物**

```powershell
npm run build
# USE_MOCK 这个标识符应该【完全消失】（说明被静态求值了）
Get-ChildItem dist -Recurse -File | Select-String -Pattern 'USE_MOCK'
# 期望：没有任何输出
```

**方法 3（最可靠）：起一个本地静态服务器，亲眼看它请求不请求后端**

```powershell
npm run build
npm run preview        # 起一个本地静态服务器，模拟"部署后"的环境
```

然后打开它给的地址，按 F12 看 **Network** 面板：

- **能看到 `/api/v1/...` 的请求** → 走真后端 ✓
- **只有假数据、没有任何网络请求** → 还在用假数据 ✗

> 注意：方法 3 会因为"后端没起"而报错（请求失败），**这是对的**——
> 报错说明它真的去请求了。如果完全不报错、界面还有数据，那才是假数据。

## 三、顺带修掉的问题：devtools 不该进生产包

`vite.config.ts` 里原本是：

```ts
plugins: [vue(), vueJsx(), vueDevTools()]
```

`vueDevTools()` 是**开发调试工具**。放在生产构建里有两个坏处：

1. 增加产物体积
2. **会在线上公网暴露一个 `__devtools__` 路径**

现在改成只在开发模式启用：

```ts
plugins: [vue(), vueJsx(), ...(mode === 'development' ? [vueDevTools()] : [])]
```

**验证方法：**

```powershell
npm run build
Get-ChildItem dist -Recurse | Where-Object { $_.Name -match 'devtools' }
# 期望：没有任何输出
Get-Content dist\index.html | Select-String 'devtools'
# 期望：没有任何输出
```

## 四、交付物长什么样

### dist 的结构

```
dist/
├── index.html          入口（必须放在网站根目录）
├── favicon.ico
└── assets/             36 个文件：js / css
```

### ⚠️ 一个部署前提：网站根目录

`dist/index.html` 里所有资源引用都是**以 `/` 开头的绝对路径**：

```html
<script type="module" crossorigin src="/assets/index-CDSLT0Xj.js"></script>
<link rel="stylesheet" crossorigin href="/assets/index-Bt4xUbwb.css">
```

所以**必须部署在域名的根路径下**（比如 `https://xxx.edu.cn/`）。

如果后端要部署在子路径下（比如 `https://xxx.edu.cn/lostfound/`），
需要先改 `vite.config.ts` 的 `base`：

```ts
export default defineConfig({
  base: '/lostfound/',
  // ...
})
```

**这件事要提前问后端，别等部署完才发现页面一片白。**

### 打包成 zip 交给后端

```powershell
npm run build
Compress-Archive -Path 'dist\*' -DestinationPath 'dist.zip' -Force
```

⚠️ 注意 `dist\*` 是**把内容**放进 zip（`index.html` 在 zip 的根），这是对的。
正确的 zip 打开后应该是：

```
index.html
favicon.ico
assets/...
```

**不要**打成 `dist/index.html` 这种多一层目录的结构，后端解压后还要自己挪。

## 五、验证清单（照这个走一遍）

改完任何与打包相关的东西，按顺序验证：

| # | 做什么 | 期望结果 |
|---|---|---|
| 1 | `Select-String -Path 'src\mock\index.ts' -Pattern 'USE_MOCK'` | 是 `!import.meta.env.PROD` |
| 2 | `npm run type-check` | 0 错误 |
| 3 | `npm run build` | 退出码 0，最后一行是 `✓ built in ...` |
| 4 | 在 `dist` 里搜 `devtools` | 没有任何输出 |
| 5 | 在 `dist` 里搜写死的域名 | 没有（只有 axios 库自带的 `http://localhost` 兜底，那是库的代码） |
| 6 | 打开 `dist/index.html` | 资源引用是以 `/` 开头 |
| 7 | `npm run preview` + F12 Network | 能看到 `/api/v1/...` 请求 |

**⚠️ 铁律：`npm run build` 失败时，不要相信任何基于旧 `dist` 做的验证。**
打包器失败时旧产物还在，很容易得出"没问题"的错误结论。

## 六、已知未解决的问题（不影响功能）

### `dist` 里的 `mock-*.js` 有多大

产物里有一个 `mock-*.js`，**225 KB（gzip 86 KB）**。

**它的名字有严重误导** —— 它其实是个**共享 chunk**，里面同时装着：

- Vue / Element Plus 的运行时代码
- 以及 mock 模块的残留

### 实测结论（做了 4 轮对比测试）

| 测试 | 结果 |
|---|---|
| 写死 `USE_MOCK = false` | 体积**不变** |
| 加 `sideEffects: false` | **不变** |
| 去掉 `vueDevTools()` | **不变** |
| 产物里搜 `USE_MOCK` / `if(!1)` | **0 处** → 说明分支**已被静态消除** |
| 产物里搜 `mockLogin` 的调用点 | **0 处** → 假函数成了孤儿，不会被调用 |

**所以：`if (USE_MOCK)` 的分支确实被消除了、假函数也确实不会被执行。
但它们的 export 声明被当前打包器保留了，于是 11 处假数据字符串**
（`cdn.example.com`、李四、王老师等）**留在包里**。

### 结论：这是体积问题，不是功能或安全问题

- 那些字符串**不会被展示**给用户
- 不影响任何功能
- 不影响安全（不是密钥之类的东西）

### 要彻底解决的话

需要让生产构建**不解析** `@/mock` 这个模块，例如在 `vite.config.ts` 里
按 mode 把 `@/mock` 别名指向一个空实现。但那涉及 20 多个 mock 函数要写空实现 +
重新验证全部接口，**验收前不动它，避免引入新风险**。

## 七、⚠️ 还没做的事：T18 联调

**这是当前最大的未知数，必须知道。**

在修 `USE_MOCK` 之前，生产构建跑的是假数据，所以**从来没有真正连过后端**。
现在生产构建首次指向真实后端，但**真后端一直不可用**，因此：

> **各接口的字段是否与契约完全一致，尚未实测。**

后端就绪后需要按 `05-前端接口待办清单` 的 T18 逐项联调，重点核对：

| 项 | 为什么要注意 |
|---|---|
| 响应包装形状 | 有没有外层 `{ code, message, data }`（代码里做了兼容，但要实测） |
| `msg` / `message` 字段 | 契约里两种都出现过，代码里两种都收，需确认后端给哪个 |
| 字段命名 | 内部一律驼峰，只有 `src/api/*.ts` 里转下划线；后端返回的实际字段名要对得上 |
| `/api/v1` 前缀 | 和后端实际路由是否一致 |
| 登录返回结构 | token / refreshToken / role / userId 的实际字段名 |
| 业务码 | 契约 22 个业务码，后端实际返回的是否一致 |

**联调的做法**：把 `USE_MOCK` 临时设为 `false` 起 `npm run dev`（vite proxy 会转发到
`http://127.0.0.1:8000`），逐个页面点一遍，对照 Network 面板看真实响应。

## 八、常用命令速查

| 场景 | 命令 |
|---|---|
| 本地开发（用假数据） | `npm run dev` → `http://localhost:5173/` |
| 类型检查 | `npm run type-check` |
| 生产打包 | `npm run build` |
| 本地预览打包结果 | `npm run preview` |
| 代码检查 | `npm run lint` |
| 格式化 | `npm run format` |

> ⚠️ `npm run format` 会**同时格式化 `src/*.md`**，把 markdown 表格补空格、
> 让文件体积明显变大（导读从 28.8 KB 涨到 41 KB）。
> 如果不想让它动文档，只格式化代码：
>
> ```powershell
> npx prettier --write "src/**/*.{ts,vue}"
> ```

> ⚠️ 本地开发访问要用 `http://localhost:5173/`，**不要用 `http://127.0.0.1:5173/`**
> —— vite 默认只绑 IPv6 的 `::1`。
